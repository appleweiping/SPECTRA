# PAPER ACCEPTANCE CONTRACT — SPECTRA (ICCAD)

status: proposed (round 0)
Inputs: NARRATIVE_REPORT.md, paper/ (current draft), results/, EXPERIMENT_LOG.md.
Each assertion is checked against the compiled `paper/main.pdf` and the named files.

## Venue / form
A1. The PDF uses `acmart` sigconf with `review,anonymous`; body (text, figures, tables) ends on or before page 8 and
    references occupy at most one further page; no author names, affiliations, acknowledgements or non-anonymous URLs.
A2. `paper/main.log` contains no undefined references/citations and no overfull hbox wider than 5 pt.

## Traceability
A3. Every number in the abstract, introduction and experiment text is produced by a macro in `paper/numbers.tex`, which
    `scripts/paper_numbers.py` regenerates from `results/` (no hand-typed result numbers in `sections/*.tex` except
    benchmark constants that are defined by construction, e.g. 45 PVT conditions, budgets).
A4. Every table in `paper/tables/` is generated by `scripts/make_tables.py` from `results/`; every data figure in
    `paper/figs/*.pdf` by `scripts/make_figures.py`.
A5. The program listing (Fig. 2) is a verbatim, abridged excerpt (elisions marked `...`) of a program stored in
    `results/raw/E1/spectra/*/s0.json`, and its caption names the task tier and experiment.

## Headline claims and scope
A6. The headline comparison (abstract + intro) reports the pre-registered primary endpoint (T3 ∪ robust) with 95%
    cluster-bootstrap CIs and paired per-task tests (Holm-corrected), and states the number of common tasks it is
    computed on.
A7. Every comparative claim of the form "SPECTRA beats X" is either backed by a Holm-corrected p < 0.05 on the primary
    endpoint, or is worded as a point estimate / trend without the word "significant".
A8. The abstract and intro state that all methods use the same LLM, the same knowledge cards, and identical call and
    simulation budgets, and give the budgets.
A9. The negative results appear in the abstract or intro and in the experiments: (i) diagnosis does not improve fault
    localisation in isolation (E4, with the Haiku degradation), (ii) intent programs mispredict second-order metrics.
A10. Ablation claims (Sec. ablation) name the subset size and seed count; a component is called "necessary" only if
    removing it lowers success with a non-overlapping or paired-test-supported difference; otherwise "contributes" or
    "no measurable effect".
A11. The PVT section reports SPECTRA vs. TT-only design vs. genbo_full on the same robust subset, with simulation
    cost, and the failing-condition breakdown comes from `results/pvt_failure_conditions.json`.

## Honesty / limitations
A12. Limitations name at least: schematic-level only (no parasitics); template-derived certified tier; tiered seeds
    (1–2 per task) and the robust budget change (1200 → 600, truncation scoring); dropped arms (Gen+CMA-ES, all-corner
    strategy, template oracle, Sonnet backbone, infeasible-spec controls); single model family for executor and reviewer.
A13. Baselines are described as "AnalogCoder-style" / "AnalogCoder-Pro-style" re-implementations, never as the
    original systems, and the description states what each re-implementation shares with SPECTRA (PDK sheet,
    knowledge cards, budgets).
A14. Benchmark description gives task counts per family and tier consistent with `data/bench/*.jsonl` and states how
    feasibility certificates are produced and re-verified.

## Completeness
A15. Related work cites and positions against at least: AnalogCoder, AnalogCoder-Pro, one PVT-aware LLM sizing method,
    one gm/Id-based automation method, and one analog LLM benchmark; `paper/CITATION_AUDIT.md` verdict is PASS for the
    final bib.
A16. Reproducibility: the paper states the PDK, simulator version, LUT grid, CMA-ES settings, budgets and that code and
