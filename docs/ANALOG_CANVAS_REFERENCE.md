# Analog Canvas and Virtuoso Bridge reference alignment

This project uses [Analog Canvas](https://github.com/cascode-ai/analog-canvas) and [virtuoso-bridge-lite](https://github.com/Arcadia-1/virtuoso-bridge-lite) as engineering references for reproducible circuit-agent workflows. They are architectural guidance, not dependencies and not sources of benchmark numbers.

| Analog Canvas principle | SPECTRA implementation | Evidence or boundary |
|---|---|---|
| Circuit facts, authored testbench and specifications are kept together | A benchmark task records family, ports, testbench, quantitative specs and the rendered natural-language request | `data/bench/*.jsonl`, `spectra/bench/nl.py`, `paper/sections/bench.tex` |
| Simulation runs consume an immutable input snapshot and return separate artifacts | Each run is isolated by experiment, method, task and seed; the returned program is re-simulated outside the agent budget | `scripts/run_bench.py`, `spectra/agent/sandbox.py`, `paper/sections/bench.tex` |
| Deterministic export and structured measurements matter more than prose logs | Netlists, metric checks, PVT records and diagnosis JSON are generated from structured records; paper tables are regenerated from `results/` | `spectra/sim/evaluate.py`, `scripts/analyze.py`, `scripts/make_tables.py` |
| Agents should use typed operations and explicit lifecycle boundaries | SPECTRA keeps model calls, program execution, simulator evaluation, diagnosis and paper generation as separate stages with explicit experiment namespaces | `spectra/agent/llm.py`, `scripts/run_gpt_experiments.sh`, `scripts/finalize_paper.sh` |
| A run must be auditable and recoverable | The finalization pipeline now writes `results/evidence_manifest.json` with commit, benchmark-input hashes, raw-run hashes, model IDs, status counts and simulator version | `scripts/write_evidence_manifest.py` |
| Preparation, execution, collection and verdict are separate | Every benchmark result carries an `evidence` record with a stable run ID, input digest, lifecycle states, independent-verification marker and exact netlist/task hashes | `scripts/run_bench.py` |

Virtuoso Bridge adds a complementary execution boundary. Its default is a small one-host interface; remote/multi-session configuration is opt-in. It separates GUI host, daemon/deployment host and standalone Spectre host, requires explicit readback/check/save around design edits, treats `result.ok` plus native errors as the execution contract, uses exact PSF accessors instead of guessed aliases, and keeps offline, recorded-output and live tests distinct. SPECTRA adopts those boundaries where they fit: the ngspice runner reports explicit status/errors, each run has a stable identity and unique working directory, and evidence records distinguish execution from spec verification. The legacy fixed-topology paper artifact uses ngspice-42 on SKY130, while the current public expansion uses the separately pinned ngspice-44.2 and Xyce-7.10 server binaries. The repository does not claim Virtuoso/Spectre equivalence without a matched licensed execution path.

The references also make a boundary that SPECTRA preserves: an editor, bridge or agent can prepare a circuit and its specs, but electrical correctness comes from an independent simulator and explicit measurements. A schematic or language-model response alone is not treated as a passing result. SPECTRA therefore does not import a browser editor, hosted Canvas simulation, Virtuoso daemon, raw SKILL workflow, Spectre license, or PDK-specific GUI behavior into the benchmark; it adopts only the reproducibility and evidence boundaries that fit a server-side research evaluation.
